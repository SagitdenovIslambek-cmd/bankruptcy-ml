# Прогноз банкротства компаний: скоринговая карта vs градиентный бустинг

Практическое задание «ML-моделирование в финансах», **вариант 5 — прогноз банкротства компаний**.

* **Данные:** Kaggle «Company Bankruptcy Prediction» (Тайвань, автор fedesoriano), файл `data.csv` — 6819 компаний, 95 финансовых коэффициентов, цель `Bankrupt?` (банкротство в течение года, 0/1, 220 банкротств). Файл лежит в `data/data.csv`; если его нет — скачайте с Kaggle и положите туда.
* **Метрики варианта:** Gini и полнота при фиксированной доле проверок (5% / 10% / 20%); перевод в прибыль портфеля при LGD = 45%.
* **Модели:** WoE-скоринговая карта + логистическая регрессия (база) против LightGBM; интерпретация — SHAP; стабильность — PSI.

## Как запустить (с нуля, одной командой)

```bash
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt                          # Python 3.11 или 3.12
python run_all.py                                        # этапы 1–4 + отчёт, ~5–10 минут
```

Результат запуска:

| что | где |
|---|---|
| отчёт 5–7 стр. (Word) | `reports/report.docx` |
| сохранённая модель | `model.pkl` |
| итоговые параметры бустинга | `config.yaml` → `boosting.final_params` (перезаписывается этапом 3) |
| все числа, таблицы, графики | `artifacts/`, `reports/figures/` |

Ноутбуки `notebooks/01…04` показывают те же этапы с пояснениями; выполнить их все: `python run_all.py --notebooks`
(или открыть в Jupyter и выполнить по порядку — ноутбуки подхватывают результаты из `artifacts/`).
Тесты: `python -m unittest discover -s tests`.

> ⚠️ Если `lightgbm` не установлен, код автоматически переключается на запасной движок (sklearn `HistGradientBoosting`) и печатает предупреждение; отчёт в этом случае помечается как **предварительный**. Для сдачи запускайте с установленными `lightgbm` и `shap` (они в `requirements.txt`).

## Структура

```

src/explain.py           SHAP (summary, разбор наблюдений)
src/pipeline.py          четыре этапа задания как функции (их вызывают ноутбуки и run_all.py)
```

## Использование модели

```python
import pandas as pd
from src.predict import predict
df = pd.read_csv("data/data.csv")                        # любые строки в формате исходного файла
predict(df.tail(5))                                      # Series: калиброванная PD
predict(df.tail(5), return_decision=True)                # + решение approve/reject по порогу
```

## Как устроено, чтобы не было утечки

* Разбиение **по времени**: train — первые 70% строк, validation — следующие 15%, test (out-of-time) — последние 15%. Test открывается один раз в `step4_evaluation()`.
* Аудит признаков делается только по train; все статистики (границы винзоризации, квантили флага стресса, WoE-корзины, пороги, медианы) считаются на train.
* Гиперпараметры подбираются по `TimeSeriesSplit` внутри train, ранняя остановка и калибровка — на validation. Обычный KFold нигде не используется.
* `random_state = 42` везде, LightGBM запускается с `deterministic=True`.

## Ограничения (важно)

1. **В датасете нет даты отчёта.** Порядок строк используется как прокси времени (данные записаны хронологически; подтверждение — доля банкротств монотонно падает по порядку строк, см. отчёт, рис. 1). «Out-of-time» здесь означает «более поздние строки», а не календарный период.
2. **Мало банкротов** в validation (13) и test (19): метрики шумные, поэтому приводятся бутстреп-доверительные интервалы и CV по времени на train.
3. **Денежная оценка** использует допущение: маржа с хорошей компании 8% от EAD (`finance.margin` в `config.yaml`) — в данных нет сумм; LGD = 45% из задания; в отчёте дан анализ чувствительности к марже.
4. Тайваньские данные 1999–2009: перенос на другой рынок (в т.ч. KASE) требует переобучения.
